# 觅诗环境与发布策略（Task 3）

## 1. 环境定义
### dev
- 用途：开发联调
- 规模：单区、低配
- 数据：脱敏测试数据
- 发布：每日多次自动部署

### staging
- 用途：集成测试、性能回归、灰度演练
- 规模：接近生产拓扑
- 数据：生产结构镜像 + 脱敏样本
- 发布：主干合并后自动部署，需测试门禁

### prod
- 用途：真实用户流量
- 规模：多可用区高可用
- 数据：生产真实数据
- 发布：人工审批 + 灰度发布

## 2. 配置管理
- 配置分层：`base` + `env` + `secret`
- Secret 统一使用 KMS/Secret Manager
- 不允许明文写入仓库

## 3. CI/CD 流水线
1. 静态检查：lint + 安全扫描
2. 单元测试：核心覆盖率门槛 >= 70%
3. 构建镜像：生成不可变镜像（含 git sha）
4. 合约校验：OpenAPI 兼容性检查
5. 部署到 staging
6. 自动化回归 + 冒烟
7. 生产灰度发布（5% -> 20% -> 50% -> 100%）

## 4. 监控与告警
- SLO：
  - API 成功率 >= 99.9%
  - 核心接口 P95 < 300ms
  - 打卡成功率 >= 99.9%
- 关键看板：
  - 推荐命中率、季节推荐点击率
  - 打卡转化率、路线完成率
  - AI 任务成功率、平均耗时、成本

## 5. 回滚策略
- 任一核心指标异常自动停止灰度
- 版本回滚：`N` -> `N-1` 镜像快速回退
- 数据回滚：仅回滚可逆配置，不回滚业务事件表

## 6. 权限与审计
- 生产发布最小权限原则
- 所有发布动作需审计日志
- 紧急变更需补充事后复盘

## 7. 灾备与备份
- PostgreSQL 每日全量 + 每小时增量
- 对象存储跨区域复制
- 核心配置多区备份
- 每季度一次灾备演练
