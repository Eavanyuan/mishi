# Flutter 联调落地设计（Token Refresh / 音频播放 / 首页跳转）

## 目标
让 `mishi_app` 在真实后端模式下可完成登录态续期、首页到详情跳转和详情页音频播放交互，移除关键 TODO。

## 范围
- 拦截器自动 refresh token 并重放请求
- 首页“查看详情”跳转到 `/poem/:id`
- 详情页音频播放（播放/暂停、进度、错误提示）
- Poem 数据从真实 API 读取，不再使用 mock

## 核心决策
1. Token 刷新在 `Dio` 拦截器层完成：401 时串行刷新并重放一次原请求。
2. `PoemService` 负责将后端响应结构映射为 `Poem` 模型，避免 UI 层理解 API 细节。
3. 音频播放使用 `just_audio`，页面内管理播放器生命周期。
4. 保持最小改动：不重构全局状态机，不引入复杂会话总线。

## 非目标
- 完整注册后端流程（若后端未提供接口，仅做错误兜底）
- 音频缓存/后台播放
- 全量 Flutter widget 测试重建
