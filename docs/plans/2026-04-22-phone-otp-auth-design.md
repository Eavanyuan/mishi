# Phone OTP Auth Design

## Goal

把 Mishi 的注册/登录从“邮箱 + 用户名 + 密码”简化为主流 App 常见的“手机号 + 短信验证码”流程：首次手机号验证自动注册，已注册手机号验证后直接登录。

## User Flow

1. 用户进入登录/注册入口。
2. 默认看到手机号输入框与“获取验证码”。
3. 输入手机号后请求验证码。
4. 输入 6 位验证码并提交。
5. 后端判断手机号是否存在：
   - 已存在：签发 access/refresh token，直接登录。
   - 不存在：创建用户，默认昵称为 `诗友` + 手机号后四位，再签发 token。
6. 邮箱、用户名、密码不再作为注册必填项；保留邮箱密码登录作为兼容入口。

## Backend Design

新增两个端点：

1. `POST /v1/auth/sms/send-code`
   - 请求：`{"phone":"13800138000"}`
   - 校验手机号格式。
   - 生产模式：需要 Redis 缓存验证码。
   - 开发模式：如果 Redis 不可用，返回 `dev_mode: true` 和固定验证码 `123456`，让本地联调可运行但不伪装真实短信。
   - 限制：同手机号 60 秒冷却；验证码 5 分钟有效。

2. `POST /v1/auth/sms/login`
   - 请求：`{"phone":"13800138000","code":"123456"}`
   - 校验验证码。
   - 验证失败计数最多 5 次。
   - 验证成功后删除验证码与失败计数。
   - 查询用户，存在则登录，不存在则创建。
   - 返回现有 `LoginResponse`。

## Frontend/App Design

Flutter：

1. 注册页改为手机号验证码页。
2. 文案从“创建账户”调整为“手机号快捷登录”。
3. 移除用户名/邮箱/密码/确认密码必填输入。
4. 增加验证码输入和获取验证码按钮。
5. 提交成功后复用当前 auth provider 存 token 并跳转首页。

Web：

1. Header 登录框后续同步支持手机号验证码。
2. MVP 可以先保留邮箱密码登录，不阻塞 Flutter 主流程。

## Error Handling

1. 手机号格式错误：提示“请输入有效手机号”。
2. 验证码错误或过期：提示“验证码错误或已过期”。
3. 频繁发送：提示“验证码发送过于频繁，请稍后再试”。
4. 短信能力未配置：生产应返回明确错误；开发可返回 `dev_mode`。

## Testing

1. 后端 handler 测试：发送验证码、错误验证码、首次手机号自动注册、再次验证码登录同一用户。
2. Flutter 单元/组件测试：注册页默认展示手机号验证码流程。
3. Flutter analyze/test。
4. 后续扩展 macOS smoke 到手机号验证码登录。
