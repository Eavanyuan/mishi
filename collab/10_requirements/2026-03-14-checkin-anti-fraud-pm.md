## 1. 业务背景与价值

### 1.1 功能定位

旅行地打卡是觅诗 App 的**核心社交功能**,用于记录用户的诗词旅行足迹。

**业务价值**:
- 🎯 **用户留存**: 打卡成就系统增强用户粘性
- 📱 **社交传播**: 用户分享打卡卡片,带来自然增长
- 📊 **数据资产**: 真实打卡数据可用于运营分析和推荐优化

**风险点**:
- 🔴 **虚假定位作弊**: 用户使用虚拟定位工具刷打卡
- 🔴 **榜单公平性破坏**: 作弊用户占据榜单,真实用户流失
- 🔴 **数据污染**: 虚假打卡数据影响推荐算法质量

### 1.2 业务目标

**主目标**: 保证打卡榜单的公平性和数据真实性

| 目标 | 指标 | 目标值 |
|-----|------|--------|
| 拦截作弊 | 作弊拦截率 | >= 90% |
| 保护真实用户 | 误杀率 | < 5% |
| 快速响应 | 风控判定耗时 | < 100ms |
| 人工审核效率 | 申诉处理时效 | < 24 小时 |

## 3. 防作弊规则设计

### 3.1 规则分层

采用**多层防御策略**,从低成本到高成本逐层过滤:

| 层级 | 规则类型 | 检查内容 | 成本 | 拦截率 |
|-----|---------|---------|------|--------|
| **L1: 基础规则** | 硬性阈值 | 距离、时间、频率 | 极低 | 50-60% |
| **L2: 行为规则** | 统计分析 | 速度、轨迹、设备 | 低 | 30-35% |
| **L3: 设备指纹** | 设备识别 | 虚拟机、模拟器、Root/越狱 | 中 | 5-10% |
| **L4: 人工审核** | 复杂判断 | 疑似作弊的边缘case | 高 | 1-5% |

**总拦截率目标**: >= 90%

---

### 3.2 L1: 基础规则 (强制规则)

#### 规则 1.1: 距离检查

**规则**: 用户定位必须在地理围栏内

```
if (distance_to_poi > 100 meters) {
  reject("距离过远,请靠近地点后重试")
}
```

**验收标准**:

```gherkin
Given: 用户定位坐标 (39.9042, 116.4074)
  And: "天安门"地理围栏中心 (39.9047, 116.4074)
When: 计算距离 = 55 米
Then: 距离检查通过 (< 100 米)

Given: 用户定位坐标 (39.9100, 116.4074)
  And: "天安门"地理围栏中心 (39.9047, 116.4074)
When: 计算距离 = 590 米
Then: 距离检查不通过 (> 100 米)
  And: 拒绝打卡
```

**埋点**:

| 指标 | 事件 ID | 属性 |
|-----|---------|------|
| 距离检查失败 | `checkin_distance_fail` | `poi_id`, `distance`, `threshold` |

---

#### 规则 1.2: 定位精度检查

**规则**: GPS 定位精度必须 < 50 米

```
if (gps_accuracy > 50 meters) {
  reject("定位精度不足,请在空旷处重试")
}
```

**原因**: 精度过低可能是信号干扰或虚拟定位

**验收标准**:

```gherkin
Given: 用户 GPS 精度 = 20 米
Then: 精度检查通过

Given: 用户 GPS 精度 = 80 米
Then: 精度检查不通过
  And: 提示用户改善定位环境
```

**埋点**:

| 指标 | 事件 ID | 属性 |
|-----|---------|------|
| 精度检查失败 | `checkin_accuracy_fail` | `poi_id`, `accuracy`, `threshold` |

---

#### 规则 1.3: 重复打卡检查

**规则**: 同地点 1 小时内不可重复打卡

```
last_checkin_time = get_last_checkin(user_id, poi_id)
if (now - last_checkin_time < 1 hour) {
  reject("该地点已打卡,1 小时后可再次打卡")
}
```

**目的**: 防止刷榜行为

**验收标准**:

```gherkin
Given: 用户在"琉璃厂"的上次打卡时间为 30 分钟前
When: 用户再次尝试打卡
Then: 重复检查不通过
  And: 提示: "该地点 XX 分钟后可再次打卡"
```

**埋点**:

| 指标 | 事件 ID | 属性 |
|-----|---------|------|
| 重复打卡拦截 | `checkin_duplicate_block` | `poi_id`, `last_checkin_time`, `cooldown_remaining` |

### 3.3 L2: 行为规则 (统计规则)

#### 规则 2.1: 速度检查

**规则**: 两次打卡间隔 < 5 分钟且距离 > 500 米,判定为异常

```
if (time_gap < 5 minutes && distance > 500 meters) {
  speed = distance / time_gap
  if (speed > 6 km/h) {  // 正常步行速度
    risk_score += 50  // 标记风险
  }
}
```

**目的**: 检测瞬移行为 (虚拟定位切换)

**验收标准**:

```gherkin
Given: 用户在"天安门"打卡 (时间: 10:00:00)
When: 用户 3 分钟后在"故宫"打卡 (距离: 1000 米)
Then: 速度 = 1000m / 3min = 20 km/h (异常)
  And: 风险评分 +50
  And: 触发人工审核
```

**埋点**:

| 指标 | 事件 ID | 属性 |
|-----|---------|------|
| 速度异常检测 | `checkin_speed_anomaly` | `user_id`, `prev_poi`, `curr_poi`, `speed`, `time_gap` |

---

#### 规则 2.2: 单日打卡次数检查

**规则**: 单用户单日打卡 > 20 次,标记异常

```
daily_count = count_checkins_today(user_id)
if (daily_count > 20) {
  risk_score += 30
  alert_reviewer()  // 人工审核
}
```

**目的**: 检测批量刷榜行为

**验收标准**:

```gherkin
Given: 用户今日已打卡 22 次
When: 用户再次尝试打卡
Then: 触发单日次数异常
  And: 风险评分 +30
  And: 推送人工审核队列
```

**埋点**:

| 指标 | 事件 ID | 属性 |
|-----|---------|------|
| 单日次数异常 | `checkin_daily_count_anomaly` | `user_id`, `daily_count`, `threshold` |

---

#### 规则 2.3: 深夜打卡异常

**规则**: 23:00-06:00 期间打卡,且定位精度 > 30 米,标记异常

```
if (is_night_time() && gps_accuracy > 30 meters) {
  risk_score += 20  // 疑似室内虚拟定位
}
```

**目的**: 深夜户外打卡较少,且精度差可能是室内作弊

**验收标准**:

```gherkin
Given: 当前时间 = 02:30
  And: 用户 GPS 精度 = 45 米
When: 用户打卡
Then: 触发深夜异常规则
  And: 风险评分 +20
```

**埋点**:

| 指标 | 事件 ID | 属性 |
|-----|---------|------|
| 深夜打卡异常 | `checkin_night_anomaly` | `user_id`, `poi_id`, `checkin_time`, `accuracy` |

#### 规则 3.2: Root/越狱设备检测

**规则**: 检测设备是否已 Root (Android) 或越狱 (iOS)

**策略**: 
- **警告模式** (V1): 检测到 Root/越狱,记录但不拦截
- **拦截模式** (V2): 高风险用户 + Root/越狱 → 拦截

**验收标准**:

```gherkin

  And: 用户风险评分 > 80
When: 尝试打卡
Then: 拒绝打卡
  And: 提示: "检测到设备安全风险"
```

**埋点**:

| 指标 | 事件 ID | 属性 |
|-----|---------|------|
| Root/越狱检测 | `checkin_rooted_device` | `user_id`, `device_type`, `is_rooted` |

### 3.5 风险评分模型

采用**累积评分制**,综合多个规则的风险得分:

```
总风险评分 = Σ (各规则触发的评分)

if (总评分 >= 100) {
  拒绝打卡
} else if (总评分 >= 60) {
  打卡成功,但标记风险用户供人工审核
} else {
  正常通过
}
```

**评分权重**:

| 规则 | 触发评分 | 说明 |
|-----|---------|------|
| 距离过远 | 直接拒绝 | 硬性规则 |
| 精度不足 | 直接拒绝 | 硬性规则 |
| 重复打卡 | 直接拒绝 | 硬性规则 |
| 速度异常 | +50 | 高风险 |
| 单日次数异常 | +30 | 中风险 |
| 设备多账号 | +40 | 中风险 |
| 深夜打卡 | +20 | 低风险 |
| Root/越狱设备 | +10 | 观察风险 |

**示例**:

```
用户 A:
- 速度异常 (+50)
- 深夜打卡 (+20)
- Root 设备 (+10)
总评分 = 80 → 打卡成功,标记风险用户

用户 B:
- 速度异常 (+50)
- 单日次数异常 (+30)
- 设备多账号 (+40)
总评分 = 120 → 拒绝打卡
```

## 4. 幂等性设计

### 4.1 目标

防止网络抖动或用户重复点击导致重复打卡记录。

### 4.2 幂等键设计

**幂等键**: `checkin:{user_id}:{poi_id}:{time_bucket}`

```
time_bucket = floor(timestamp / 3600)  // 按小时分桶
idempotent_key = f"checkin:{user_id}:{poi_id}:{time_bucket}"
```

**流程**:

```python
if redis.exists(idempotent_key):
    return "重复请求,已拦截"

# 设置幂等键,TTL = 1 小时
redis.setex(idempotent_key, 3600, "1")

# 执行打卡逻辑
perform_checkin(user_id, poi_id)
```

### 4.3 验收标准

```gherkin
Given: 用户在"琉璃厂"打卡成功
When: 用户在 10 秒内再次点击打卡 (网络重复)
Then: 系统检测到幂等键已存在
  And: 返回: "打卡已完成,请勿重复提交"
  And: 不写入重复记录
```

**埋点**:

| 指标 | 事件 ID | 属性 |
|-----|---------|------|
| 幂等拦截 | `checkin_idempotent_block` | `user_id`, `poi_id`, `retry_count` |

## 5. 降级策略

当风控系统异常或压力过大时,采取降级措施保证核心功能可用。

### 5.1 降级级别

| 级别 | 触发条件 | 降级措施 |
|-----|---------|---------|
| **L1: 轻度降级** | 风控延迟 > 200ms | 跳过 L3 设备指纹检查 |
| **L2: 中度降级** | 风控延迟 > 500ms | 仅保留 L1 基础规则 |
| **L3: 重度降级** | 风控服务不可用 | 全部放行,事后审计 |

### 5.2 验收标准

```gherkin
Given: 风控服务响应延迟 > 500ms
When: 触发中度降级
Then: 仅执行距离/精度/重复检查 (L1)
  And: 跳过速度/次数/设备检查 (L2/L3)
  And: 记录降级事件
  And: 打卡成功,但标记"降级通过"供事后审计
```

**埋点**:

| 指标 | 事件 ID | 属性 |
|-----|---------|------|
| 风控降级触发 | `checkin_risk_downgrade` | `downgrade_level`, `reason`, `latency` |

## 6. 人工审核机制

### 6.1 审核队列

**自动推送审核条件**:
- 风险评分 >= 60 且 < 100 (疑似作弊)
- 用户申诉
- 单日打卡 > 20 次
- 连续 3 天触发速度异常

### 6.2 审核流程

```
风险用户 → 审核队列 → 人工判断 → 处理决策

处理决策:
- 确认作弊 → 封禁账号 + 清除打卡记录 + 加入黑名单
- 误判 → 恢复权限 + 优化规则
- 待观察 → 标记观察用户,持续监控
```

### 6.3 审核工具需求

**CMS 后台功能**:
- 审核队列看板 (待审核数量、优先级)
- 用户打卡轨迹可视化 (地图展示)
- 风险规则命中详情
- 一键封禁/解封
- 批量处理

### 6.4 审核 SLA

| 优先级 | 定义 | 处理时效 |
|-------|------|---------|
| **P0: 紧急** | 单日打卡 > 50 次 | < 2 小时 |
| **P1: 高** | 风险评分 >= 80 | < 24 小时 |
| **P2: 中** | 风险评分 60-79 | < 72 小时 |
| **P3: 低** | 用户申诉 | < 7 天 |
