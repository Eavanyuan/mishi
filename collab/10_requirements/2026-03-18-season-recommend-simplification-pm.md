## 1. 背景

基于项目危机状态和降级版MVP定义（`2026-03-18-project-crisis-recovery-pm.md`），季节推荐算法需要大幅简化以匹配当前技术约束和时间压力。

**原计划**: 复杂算法，考虑季节匹配度、时段因子、冷启动策略  
**现实约束**: 数据库严重阻塞，Backend执行能力有限，时间极度紧张  
**决策**: 采用**静态推荐**方案，移除算法复杂性

## 2. 简化方案

### 2.1 核心变更

| 维度 | 原方案 | 简化方案 | 理由 |
|------|--------|----------|------|
| 推荐逻辑 | 动态算法计算 | 静态列表返回 | 无需数据库查询，无算法复杂度 |
| 季节匹配 | 实时计算匹配度 | 预置分类列表 | 简化实现，保证基础体验 |
| 时段因子 | 复杂时段标签匹配 | 移除时段因子 | 非核心功能，可延后 |
| 冷启动 | 特殊处理新诗词 | 统一静态列表 | 简化数据管理 |

### 2.2 静态推荐方案详情

**API端点**: `GET /poems/recommend`

**请求参数**:
```json
{
  "season": "spring",  // 可选: "spring", "summer", "autumn", "winter"
  "limit": 5           // 可选: 返回数量，默认5
}
```

**响应格式**:
```json
{
  "poems": [
    {
      "id": "poem_001",
      "title": "春晓",
      "author": "孟浩然",
      "dynasty": "唐",
      "content_preview": "春眠不觉晓，处处闻啼鸟...",
      "audio_url": "https://cdn.mishi.app/audio/poem_001.mp3",
      "season_tags": ["spring"],
      "recommend_reason": "春季经典诗篇"
    }
  ],
  "recommendation_type": "static_seasonal"
}
```

**实现方式**:
1. **预置数据**: 为每个季节预置10-15首经典诗词
2. **随机选择**: 每次请求从对应季节列表中随机选择limit首
3. **无算法**: 无需用户数据、无需实时计算、无需数据库查询

### 2.3 数据准备要求

**诗词筛选标准**:
1. 每个季节选择10-15首最具代表性的经典诗词
2. 确保诗词内容质量高，知名度广
3. 优先选择已有音频录制的诗词
4. 确保版权清晰，可公开使用

**示例列表**:
- **春季**: 《春晓》、《钱塘湖春行》、《咏柳》、《春夜喜雨》...
- **夏季**: 《小池》、《晓出净慈寺送林子方》、《夏意》...
- **秋季**: 《山行》、《秋夕》、《登高》、《枫桥夜泊》...
- **冬季**: 《江雪》、《梅花》、《白雪歌送武判官归京》...

## 3. 验收标准更新

### 3.1 原验收标准回顾 (2026-03-17-season-recommend-clarification-pm.md)

**复杂算法标准**:
- 季节匹配度计算 (完全匹配1.0, 部分匹配0.8, 跨季0.3, 无标注0.5)
- 时段因子权重10%
- 冷启动策略 (新诗词默认分0.5)
- 多因子加权排序

### 3.2 简化版验收标准

**静态推荐标准**:
```gherkin
Given: 用户请求季节推荐
  And: 当前季节为 "spring"
When: 调用 /poems/recommend?season=spring
Then: 返回3-5首春季预置诗词
  And: 响应时间 < 200ms
  And: 返回的诗词都包含 "spring" season_tags
  And: 每次请求返回的诗词可能不同 (随机选择)
```

**性能标准**:
- 响应时间P95 < 200ms (静态数据，无计算)
- 可用性 >= 99.9% (无外部依赖)
- 支持QPS >= 1000 (轻量级端点)

**数据质量标准**:
- 每个季节至少10首预置诗词
- 所有预置诗词都有完整元数据 (标题、作者、朝代、内容)
- 至少80%的预置诗词有音频文件

### 3.3 成功指标调整

| 指标 | 原目标 | 简化版目标 | 说明 |
|------|--------|------------|------|
| 推荐点击率 | >= 30% | >= 20% | 静态推荐质量较低，目标调整 |
| 用户满意度 | >= 4.0/5.0 | >= 3.5/5.0 | 接受基础体验 |
| 算法计算耗时 | < 50ms | 0ms (静态) | 无算法计算 |
| 数据标注覆盖率 | >= 80% | 100% (预置) | 预置数据，完全控制 |
