## 用户故事拆解

### 功能 1: 到地触发推荐 ⭐⭐⭐⭐⭐ (P0)

#### 用户故事 1.1: 地理围栏触发推荐卡

**故事描述**:
> 作为一名旅行用户,我希望到达历史地点后自动收到诗词推荐卡片,这样我就不需要主动搜索,能更沉浸地体验当下场景。

**业务价值**:
- 核心差异化功能,从"被动搜索"变为"场景主动推送"
- 提升用户体验的关键路径
- 预计点击率目标: >= 25%

**验收标准** (Given/When/Then):

```gherkin
Given: 用户已授权定位权限
  And: 用户位于"黄鹤楼"地理围栏 100 米内
  And: 用户在该位置停留超过 30 秒
When: 系统检测到用户满足触发条件
Then: 系统推送推荐卡片,显示《黄鹤楼送孟浩然之广陵》
  And: 推荐卡包含: 诗名、作者、一句导语、距离信息、季节标签
  And: 推荐卡弹出延迟 < 2 秒
  And: 触发距离误差 < 50 米
```

**埋点指标**:

| 指标名称 | 事件 ID | 触发时机 | 关键属性 |
|---------|---------|---------|---------|
| 地理触发成功 | `geo_trigger_success` | 围栏命中且推送卡片 | `poi_id`, `poem_id`, `distance`, `stay_duration` |
| 地理触发失败 | `geo_trigger_fail` | 围栏命中但推送失败 | `poi_id`, `error_code`, `error_msg` |
| 推荐卡曝光 | `recommend_card_show` | 推荐卡展示 | `poi_id`, `poem_id`, `season_tag`, `trigger_type` |
| 推荐卡点击 | `recommend_card_click` | 用户点击"去感受" | `poi_id`, `poem_id`, `click_duration_ms` |
| 推荐卡关闭 | `recommend_card_dismiss` | 用户关闭卡片 | `poi_id`, `poem_id`, `dismiss_type` |

**风险识别**:

| 风险 | 概率 | 影响 | 应对策略 |
|-----|------|------|---------|
| 定位漂移导致误触发 | 高 | 高 | 多信号融合(GPS+WiFi+基站),低置信度二次确认 |
| 网络延迟导致推送延迟 | 中 | 中 | 本地缓存热门诗词,优先展示缓存内容 |
| 同地点重复触发打扰用户 | 中 | 高 | 触发冷却策略: 同地点 24 小时内不重复强提醒 |
| 用户拒绝定位权限 | 低 | 高 | 降级体验: 允许手动选择城市浏览 |

**依赖关系**:
- **前置**: 无
- **后置**: 诗词详情展示 (用户故事 2.1)
- **技术依赖**: 
  - Geo Service: `/geo/nearby` 接口
  - Recommend Service: `/poems/recommend` 接口
  - 地理围栏数据已录入

#### 用户故事 1.2: 触发冷却与历史记录

**故事描述**:
> 作为一名用户,我希望系统记住我已经看过的地点推荐,避免同一地点反复打扰我。

**业务价值**:
- 避免用户反感,提升产品好感度
- 平衡推送频率与用户体验

**验收标准**:

```gherkin
Given: 用户在"黄鹤楼"触发过推荐卡
  And: 距离上次触发时间 < 24 小时
When: 用户再次进入"黄鹤楼"围栏
Then: 系统不弹出推荐卡
  And: 但在地图上保留该点位标记
  And: 用户可点击标记主动查看
```

**埋点指标**:

| 指标名称 | 事件 ID | 触发时机 | 关键属性 |
|---------|---------|---------|---------|
| 触发冷却拦截 | `trigger_cooldown_block` | 冷却期内命中围栏 | `poi_id`, `last_trigger_time`, `cooldown_remaining_ms` |
| 主动点击点位 | `poi_marker_click` | 用户点击地图点位 | `poi_id`, `poem_id`, `is_visited` |

**风险识别**:
- 冷却期过长可能错过最佳推荐时机 → 允许用户在设置中自定义冷却时长(1h/6h/24h)

**依赖关系**:
- **技术依赖**: Redis 缓存用户触发历史

### 功能 2: 诗词详情展示 ⭐⭐⭐⭐⭐ (P0)

#### 用户故事 2.1: 诗词详情页完整展示

**故事描述**:
> 作为一名用户,我希望看到诗词的完整内容、权威解读和背景故事,这样我能深入理解诗词的意境和历史背景。

**业务价值**:
- 核心内容消费场景
- 权威解读是产品差异化价值
- 预计完读率目标: >= 35%

**验收标准**:

```gherkin
Given: 用户从推荐卡点击"去感受"
When: 进入诗词详情页
Then: 页面展示以下内容:
  - 顶部标签: 今称、古称、最佳季节
  - 标题: 诗名 + 作者朝代
  - 正文: 诗句全文 (大字号,行高 1.9)
  - 解读卡: 教材版解读 (默认)
  - 来源标注: 出版社/典籍名称
  - CTA 按钮: "朗读"、"生成动画"、"收藏"、"分享"
And: 页面加载时间 < 1.5 秒
And: 图片/字体渲染完整无错位
```

**埋点指标**:

| 指标名称 | 事件 ID | 触发时机 | 关键属性 |
|---------|---------|---------|---------|
| 详情页进入 | `poem_detail_enter` | 进入详情页 | `poem_id`, `entry_source`, `load_time_ms` |
| 详情页滚动 | `poem_detail_scroll` | 用户滚动浏览 | `poem_id`, `scroll_depth_percent`, `time_spent_ms` |
| 详情页完读 | `poem_detail_complete` | 滚动到底部 | `poem_id`, `read_time_ms` |
| CTA 按钮点击 | `poem_detail_cta_click` | 点击朗读/动画/收藏/分享 | `poem_id`, `cta_type`, `click_position` |

**风险识别**:
- 内容过长导致用户流失 → 默认折叠背景故事,用户点击"展开"查看
- 来源标注不清晰影响信任度 → 强制显示来源,支持点击查看完整引用

**依赖关系**:
- **前置**: 到地触发推荐 (用户故事 1.1)
- **技术依赖**: 
  - Content Service: `/poems/{id}` 接口
  - 内容数据已审核发布

### 功能 3: 语音朗读 ⭐⭐⭐⭐⭐ (P0)

#### 用户故事 3.1: 语音朗读播放

**故事描述**:
> 作为一名用户,我希望能听到诗词的语音朗读,这样我可以闭眼沉浸式感受诗词的韵律和意境。

**业务价值**:
- 沉浸式体验的核心功能
- 预计播放完成率目标: >= 40%

**验收标准**:

```gherkin
Given: 用户在诗词详情页
When: 点击"朗读"按钮
Then: 进入全屏播放页
  And: 显示诗词封面卡 (高 220px)
  And: 诗句同步高亮显示 (高亮字色为朱砂 #B23A2B)

  And: 支持氛围音开关 (默认关闭)
  And: 音频加载时间 < 3 秒
  And: 播放流畅无卡顿
```

**埋点指标**:

| 指标名称 | 事件 ID | 触发时机 | 关键属性 |
|---------|---------|---------|---------|
| 朗读开始 | `audio_play_start` | 点击播放按钮 | `poem_id`, `audio_url`, `play_mode` |
| 朗读暂停 | `audio_play_pause` | 点击暂停 | `poem_id`, `play_progress_percent`, `pause_time_ms` |

**风险识别**:

- 网络波动导致卡顿 → 自动降低音质,优先保证流畅度
- 后台播放电量消耗 → 提供"省电模式"选项,关闭后台刷新

**依赖关系**:
- **技术依赖**: 
  - Media Service: `/audio/{poem_id}` 接口
  - TTS 预生成音频 (热门 100 首)

### 功能 4: 季节标签推荐 ⭐⭐⭐⭐☆ (P0)

#### 用户故事 4.1: 季节匹配推荐

**故事描述**:
> 作为一名用户,我希望系统能根据当前季节推荐最契合的诗词,这样我能感受到"诗中有景、景中有诗"的时令共鸣。

**业务价值**:
- 产品差异化亮点
- 提升推荐贴合度
- 预计季节匹配推荐点击率: >= 30%

**验收标准**:

```gherkin
Given: 用户位于"西湖"围栏内
  And: 当前时间为 2026-09-07 (白露节气,秋季)
When: 系统触发推荐
Then: 推荐卡显示季节标签 "秋·白露"
  And: 推荐诗词为季节匹配度高的诗词 (如《钱塘湖春行》春季,《饮湖上初晴后雨》夏季)
  And: 推荐排序中季节因子权重 >= 20%
```

**排序算法** (待架构师细化):

```
推荐得分 = 距离因子 × 0.4 
        + 热度因子 × 0.3 
        + 季节匹配因子 × 0.2 
        + 时段因子 × 0.1

季节匹配因子 = {
  1.0   // 完全匹配 (诗词标注季节 == 当前季节)
  0.7   // 部分匹配 (诗词标注多季节,包含当前季节)
  0.3   // 不匹配但可读 (跨季阅读)
}
```

**埋点指标**:

| 指标名称 | 事件 ID | 触发时机 | 关键属性 |
|---------|---------|---------|---------|
| 季节推荐曝光 | `season_recommend_show` | 推荐卡显示季节标签 | `poem_id`, `season`, `solar_term`, `match_score` |
| 季节推荐点击 | `season_recommend_click` | 点击带季节标签的推荐 | `poem_id`, `season`, `click_time` |

**风险识别**:
- 季节标注错误影响推荐质量 → 内容审核时强制校验季节标注
- 跨季节旅行时推荐失真 → 提供"跨季阅读"说明,不阻断体验

**依赖关系**:
- **技术依赖**: 
  - Recommend Service: 季节权重算法
  - 诗词数据表增加 `best_season` 和 `solar_terms` 字段

### 功能 5: 旅行地打卡 ⭐⭐⭐⭐☆ (P0)

When: 用户点击"确认打卡"
Then: 系统写入打卡记录
  And: 显示 Toast: "打卡成功!已解锁琉璃厂诗词"

#### 用户故事 5.2: 打卡防作弊

**故事描述**:
> 作为产品运营者,我希望系统能识别和拦截虚假打卡行为,保证打卡榜单的公平性。

**业务价值**:
- 保护产品公平性和用户信任
- 减少作弊对运营数据的污染

**验收标准**:

```gherkin
Given: 用户尝试打卡
When: 系统检测到以下任一异常:
  - 定位漂移超过 200 米
  - 两次打卡间隔 < 5 分钟且距离 > 500 米 (速度异常)
  - 同 IP 同设备 1 小时内打卡超过 10 次
Then: 系统拒绝打卡
  And: 显示提示: "位置信息异常,请稍后再试"
  And: 记录风险日志供人工审核
```

**埋点指标**:

| 指标名称 | 事件 ID | 触发时机 | 关键属性 |
|---------|---------|---------|---------|
| 打卡风控拦截 | `checkin_risk_block` | 触发防作弊规则 | `user_id`, `poi_id`, `risk_reason`, `risk_score` |
| 打卡误杀申诉 | `checkin_appeal` | 用户申诉误杀 | `user_id`, `poi_id`, `appeal_reason` |

**风险识别**:
- 误杀正常用户 → 提供申诉入口,人工审核后解除

**依赖关系**:
- **技术依赖**: 
  - 打卡防作弊技术方案 (由 Arch Agent 设计)
  - Redis 缓存用户打卡历史

## 风险汇总

### 🔴 高优风险 (P0,需立即应对)

1. **定位漂移导致误触发**
   - 影响: 推荐卡准确性下降,用户体验受损
   - 概率: 高
   - 应对: 多信号融合 (GPS+WiFi+基站),低置信度二次确认

2. **打卡虚假定位作弊**
   - 影响: 榜单公平性破坏,真实用户流失
   - 概率: 高
   - 应对: 位置漂移检测 + 速度阈值 + 频率限制 + 人工审核

3. **网络延迟导致推送延迟**
   - 影响: 到地体验不及时,流失关键场景
   - 概率: 中
   - 应对: 本地缓存热门诗词,优先展示缓存内容

### 🟡 中优风险 (P1,需关注)

4. **音频加载失败**
   - 应对: 热门诗词预缓存,提供离线播放

5. **内容版权争议**
   - 应对: 来源强制标注,双审流程,纠错机制

6. **季节标注错误**
   - 应对: 内容审核时强制校验
