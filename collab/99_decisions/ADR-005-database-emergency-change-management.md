# ADR-005: 数据库紧急变更管理流程

## Context
在觅诗项目执行过程中，发现数据库方案提交严重逾期：
- MISHI-013 (外键约束修复方案): 逾期 4+ 小时未提交
- MISHI-014 (唯一约束调整方案): 逾期 4+ 小时未提交
- MISHI-003 (分区扩展验证): 逾期 3+ 小时无进展

这导致：
1. 项目关键路径完全阻塞，影响多个依赖任务
2. 数据完整性高风险持续存在
3. 缺乏紧急情况下的应对流程
4. 团队协作效率低下，无明确升级路径

需要建立数据库紧急变更管理流程，确保在正常流程受阻时，项目仍能推进关键风险缓解。

## Decision
建立分级数据库紧急变更管理流程，包含以下关键机制：

### 1. 紧急变更定义
符合以下任一条件的数据库变更为紧急变更：
- **P0/P1 优先级任务逾期超过 2 小时**
- **阻塞 3 个以上下游任务**
- **涉及数据完整性或安全高风险**
- **负责人无响应或无法继续工作**

### 2. 简化提交要求
紧急变更允许最小可行方案 (Minimum Viable Solution, MVS) 提交：
- **核心 SQL 脚本** (必须): 可执行的变更语句
- **数据检查步骤** (必须): 如何验证无副作用
- **回滚方案** (必须): 如何撤销变更
- **影响分析** (可选): 详细影响可后续补充
- **完整文档** (可选): 详细设计可后续补充

### 3. 快速评审通道
架构师对紧急变更提供快速评审承诺：
- **响应时间**: 收到方案后 15 分钟内提供反馈
- **评审重点**: 安全性、正确性、可回滚性
- **接受标准**: 方案解决核心风险，无明显安全隐患
- **分级批准**: 可先批准执行核心部分，后续完善

### 4. 分级执行策略
紧急变更分阶段执行：
1. **立即执行层**: 解决核心风险的高优先级变更
2. **快速跟踪层**: 重要但非紧急的优化变更
3. **标准流程层**: 常规改进和优化

### 5. 沟通升级路径
建立明确的逾期升级路径：
- **逾期 1 小时**: Coordinator 提醒
- **逾期 2 小时**: Architect 介入，提供协助
- **逾期 3 小时**: PM 介入协调，调整优先级
- **逾期 4 小时**: 危机模式，考虑替代方案

### 6. 替代方案准备
当原负责人无法完成时，准备替代方案：
- **架构师备用方案**: 提供最小可行技术方案
- **团队内重新分配**: 其他成员接管
- **范围调整**: 暂缓非关键部分，聚焦核心风险

## Alternatives
考虑过的其他选项：

### 1. 严格流程不变
- **优点**: 保持质量，避免仓促决策
- **缺点**: 项目完全阻塞，风险持续累积
- **评估**: 不适用于高风险紧急情况

### 2. 完全绕过评审
- **优点**: 最快速度执行
- **缺点**: 质量无保障，可能引入新问题
- **评估**: 风险过高，可能导致更严重问题

### 3. 人工协调替代
- **优点**: 灵活应对具体情况
- **缺点**: 依赖个人能力，无标准化流程
- **评估**: 不可扩展，难以保证一致性

### 4. 分级流程 (选择方案)
- **优点**: 平衡速度与质量，有明确升级路径
- **缺点**: 增加流程复杂度
- **评估**: 最佳平衡，可应对各种紧急程度

## Consequences
### 正面影响
1. **风险快速缓解**: 关键风险可在几小时内得到处理
2. **项目连续性**: 避免因单点阻塞导致项目停滞
3. **明确责任**: 各角色清楚在紧急情况下的职责
4. **质量保障**: 即使紧急情况也有基本质量门槛
5. **团队协作**: 建立共同应对危机的机制

### 负面影响
1. **流程复杂度**: 增加紧急流程管理负担
2. **质量风险**: 简化方案可能遗漏边缘情况
3. **团队依赖**: 可能降低正常流程的严谨性
4. **知识分散**: 替代方案可能缺乏完整上下文

### 缓解措施
1. **明确触发条件**: 仅在高风险情况下使用紧急流程
2. **事后完善机制**: 紧急执行后必须补充完整文档和测试
3. **定期演练**: 定期测试紧急流程，确保有效性
4. **经验总结**: 每次紧急变更后总结经验，优化流程

## Rollback Plan
如果需要回滚此决策：

1. **短期回滚** (流程不适应):
   - 恢复原有严格流程
   - 接受高风险任务可能逾期更久
   - 加强前期规划和资源分配

2. **中期调整** (部分流程问题):
   - 调整逾期升级时间阈值
   - 修改简化提交要求
   - 优化快速评审标准

3. **长期优化** (文化不适应):
   - 加强团队时间管理培训
   - 改进任务估算和分配机制
   - 建立更有效的日常沟通机制

**回滚触发条件**:
- 紧急流程被滥用，降低整体质量
- 团队无法有效执行分级流程
- 流程增加的管理成本超过收益
- 出现因紧急流程导致的生产事故
