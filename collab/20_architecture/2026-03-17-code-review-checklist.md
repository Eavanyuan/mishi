## 1. 数据库代码审查要点

### 1.1 表结构审查
- [ ] **命名规范**: 表名、字段名使用小写蛇形命名（snake_case）
- [ ] **数据类型**: 使用最合适的数据类型（如 INT vs BIGINT，VARCHAR vs TEXT）
- [ ] **约束完整性**: 主键、外键、唯一约束、非空约束合理
- [ ] **默认值**: 为常见字段设置合理的默认值（如 status, created_at）
- [ ] **注释**: 每个表和字段都有清晰的 COMMENT

### 1.2 索引审查
- [ ] **必要索引**: 外键字段、经常查询的字段有索引
- [ ] **复合索引**: 多字段查询使用复合索引，注意字段顺序
- [ ] **部分索引**: 对部分数据查询使用 WHERE 条件索引
- [ ] **索引类型**: 正确选择 B-tree、GIN、GIST 等索引类型
- [ ] **空间索引**: 地理位置字段使用 GIST 索引

### 1.3 约束审查
- [ ] **外键级联**: 统一使用 ON DELETE CASCADE 或 SET NULL
- [ ] **唯一约束**: 业务唯一性约束合理，考虑时间窗口
- [ ] **检查约束**: 枚举值、数值范围使用 CHECK 约束
- [ ] **非空约束**: 必要字段必须 NOT NULL

### 1.4 性能审查
- [ ] **查询计划**: 关键查询 EXPLAIN ANALYZE 结果符合预期
- [ ] **索引覆盖**: 查询能利用索引覆盖，避免全表扫描
- [ ] **连接优化**: JOIN 条件有索引支持
- [ ] **分区策略**: 大表有合理的分区策略

### 1.5 安全审查
- [ ] **权限控制**: 表级和行级安全策略（RLS）适当
- [ ] **敏感数据**: 密码哈希、token 等敏感字段加密存储
- [ ] **审计日志**: 关键操作有审计追踪
- [ ] **SQL 注入**: 使用参数化查询，避免动态 SQL

## 7. 代码审查流程

### 7.1 审查前准备
1. **代码作者**:
   - 确保代码编译通过
   - 已通过基础测试
   - 更新相关文档
   - 填写 Pull Request 描述

2. **审查者**:
   - 了解功能背景和需求
   - 准备审查环境
   - 分配足够时间

### 7.2 审查过程
1. **第一次通读**: 了解整体实现思路
2. **详细审查**: 使用本检查清单逐项检查
3. **测试验证**: 本地构建和测试
4. **性能评估**: 关键路径性能考虑
5. **安全评估**: 安全风险识别

### 7.3 审查后处理
1. **问题分类**:
   - **必须修复**: 功能错误、安全漏洞
   - **建议改进**: 代码质量、性能优化
   - **待讨论**: 设计决策、技术选型

2. **沟通反馈**:
   - 明确问题描述和建议解决方案
   - 区分主观意见和客观问题
   - 提供具体代码示例

3. **跟进闭环**:
   - 确认所有问题已解决
   - 验证修复后的代码
   - 批准合并请求
